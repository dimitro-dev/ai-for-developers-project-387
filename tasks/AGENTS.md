# tasks/ — точка входа

Маршрутизатор каталога задач: где что лежит, чем менять, куда идти за правилами. Правила треков
здесь не пересказываются — они в [`flows/`](flows/).

## Карта

| Что | Файл | Кто пишет |
|---|---|---|
| Состояние задачи — канон (гейты, checksum, depends, queue, workspace) | `<тип>/<номер>-<слаг>/task.yaml` | только CLI; руками и через Edit — никогда |
| Документы задачи — чистый Markdown без статусов | `<тип>/<номер>-<слаг>/*.md` | агент и владелец |
| Реестр задач, очередь работ, таблица legacy-id | `REGISTRY.md` | генерат `task registry`; руками не правится |
| Правила треков | `flows/full.md`, `flows/lite.md` | владелец |
| CLI и его тесты | `tools/` | по задаче; `make -C tasks gates` обязателен |
| Правила процесса: типы, статусы, треки, hash-стратегии | `tasks.config.json` | только владелец по явному решению |
| Шаблоны треков | `_template/full/`, `_template/lite/` | владелец |
| Дотиповая эпоха, как есть | `archive/` | не трогается |

Типы задач — директории: `contract/`, `infra/`, `back/`, `front/ui/`, `front/guest/`,
`front/owner/`, `process/`. Задача — `<номер>-<слаг>/`, номер трёхзначный и сквозной внутри типа.

## Навигация

`task X` = `scripts/task X` — исполняемый вход в корне репозитория. Вне репозитория с `tasks/` цель `task-check` штатно скипается.

| Нужно | Открой / запусти |
|---|---|
| Продолжить работу: стадия, активный гейт, прогресс, workspace | `scripts/task status [id]` → flow своего трека → активный документ задачи |
| Обзор всех задач или одного типа | `scripts/task list [--type X]` |
| Завести задачу или стаб будущей | критерии трека в [`flows/lite.md`](flows/lite.md) → `scripts/task new <тип> <слаг> [--lite] [--stub]` с однострочным обоснованием трека |
| Согласовать гейт — владелец сказал «согласовано», и только тогда | `scripts/task approve <id> <гейт>`; сам статус не решаешь |
| Изменить согласованный документ по существу | `scripts/task draft <id> <гейт>` — каскад автоматом; правила — [`flows/full.md`](flows/full.md), «Откаты» |
| lite-задача переросла свой трек | `scripts/task promote <id>` |
| Записать ветку, worktree, MR, спеки, зависимости | `scripts/task set <id> <путь> <значение>` / `unset` — не Edit по `task.yaml` |
| Проверить целостность: перед коммитом и в фазе «Проверка» | `scripts/task check` (входит в цель `make test`; отдельной целью — `make task-check`) |
| Изменились данные задач — обновить реестр | `scripts/task registry` |
| `check` ругается на `selfHash` после ручной правки | `scripts/task repair <id>` — принять состояние осознанно, после ревью |
| Изменил `tools/` | `make -C tasks gates` — типы и тесты CLI, обязательны |
| Закрыть задачу | чек-лист закрытия в [`flows/full.md`](flows/full.md) |
| Найти старую задачу по старому id (`front-guest-002`, `INFRA-001`) | таблица legacy-id в [`REGISTRY.md`](REGISTRY.md) |
| Понять, что делать дальше по проекту | очередь работ в [`REGISTRY.md`](REGISTRY.md) |

`init` и `migrate` — разовые команды развёртывания и переноса, в обычной работе не нужны.

Правила зон реализации (что можно менять в `apps/`, `packages/`, `infra/`, `tests/`) — во
вложенных `AGENTS.md` этих директорий, не здесь.

## Словарь

**Гейт** — точка согласования владельцем, привязанная к документу. Статусы гейта: `черновик`,
`согласовано`. Живут в `task.yaml`, меняются только через CLI. Гейты full: `brief`, `adr`, `plan`,
`result`; lite: `setup`, `result`.

**Стадия задачи** — вычисляется, не хранится: `заявлена` → `постановка` → `проектирование`
(только full) → `реализация` → `результат` → `завершена`. Показывает `task status`.

**Состояние пункта** плана или чеклиста: `в плане`, `выполняется`, `завершено`.

**Трек** — набор документов и гейтов задачи: `full` (четыре документа) или `lite` (один `task.md`).
Выбирается при создании, эскалируется `promote`, обратно не понижается.

**Канонический id** — путь без слага: `front/guest/002`, `infra/006`. Слаг — украшение, CLI
резолвит задачу по номеру. Старые id (`front-guest-002`) остаются валидными через `legacyId`.
