## Порядок и зависимости

- P01 → P02 → P03 → P04 — цепочка: схема → её тесты → PgStore → сборка в приложении.
- P05 и P06 зависят от P01–P04; между собой независимы.
- P07 зависит только от P02 (цель `db-test` существует): контур postgres с базой `minical_test`
  в CI-job `compose` есть уже сегодня, сервис `api` из P06 для БД-тестов не нужен.
- P08 — после P04–P07 (документируется фактическое состояние).
- P09 — после всех кодовых пунктов; MR готовится в конце P09 и вливается до P10.
- P10 — единственный пост-merge пункт (деплой собирается только из `main`); выполняется
  в следующей сессии владельцем или по его поручению.

## Обязательные проверки

Полный набор — цель `make gates`; что в него входит, определено только её рецептом. Результаты
фиксируются в `result.md`.

- [ ] `make gates` — фаза «Проверка» (P09)
- [ ] `make db-test` на поднятом контуре (`make db-up`) — обязательный локальный прогон
      БД-тестов, той же командой пользуется CI (P02, P09)
- [ ] `make -C <зона> gates` — после каждого пункта по затронутым зонам
- [ ] `make image-build` + smoke обоих режимов и AC6-сценарий сида (P05)
- [ ] `make lint-docs` — при правках документации (P08)

## Блокеры и открытые вопросы

- P10 выполняется после влития MR: DockHost собирает только из `main`, проверить AC5 на ветке
  невозможно. До его завершения `result` не согласуется.
- Известный флак HTTP-тестов `apps/api` (`ECONNRESET`, keep-alive undici) — существующий долг
  вне scope задачи; при флаке прогон повторяется.
