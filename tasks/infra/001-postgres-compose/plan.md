## Порядок и зависимости

```text
P01 (внешняя предпосылка: установка ПО на хост)
 └─→ P03 → P04 → P05 → P06 → P07 → P08 → P09 → P10
P02 (ветка и worktree) — до первой правки файлов, то есть до P03
```

- **P01 блокирует P03–P07.** Без Docker эти пункты можно только написать, но не проверить; писать инфраструктуру вслепую и объявлять завершённой нельзя. P08 и P09 — документация, они от Docker не зависят, но идут после, чтобы описывать проверенное поведение, а не задуманное.
- P04 требует **пустого** volume: если контур уже поднимался до появления init-скрипта, нужен `db:reset`.
- P06 зависит от P05: процедура сброса проверяется теми же командами, которые попадут в README.
- P07 пишется после P06 — шаги job повторяют последовательность, уже проверенную локально.
- Зелёный job на PR наблюдаем только после push, поэтому AC12 закрывается в P10. Push ветки санкционируется согласованием этого плана.

## Обязательные проверки

Полный список — в [`AGENTS.md`](../../../AGENTS.md), результаты фиксируются в `result.md`.

- [ ] `npm run contracts:format:check`
- [ ] `npm run generate:check`
- [ ] `npm run typecheck`
- [ ] `npm test` — контрактный gate; включает `uispec:validate` и `task:check`
- [ ] `npm run uispec:validate` — `docs/ui-spec-kit/` и UI-код `apps/client/` не меняются
- [ ] `npm test -w @minical/api` — `apps/api/` не меняется
- [ ] `npm test -w @minical/client` — `apps/client/` не меняется

`npm run task:test` и `npm run task:typecheck` не требуются: `tasks/tools/` не затрагивается.

Задача не меняет код приложений, контракт и generated-артефакты, поэтому обязательный набор здесь — регрессионная страховка. Специфические проверки контура (`docker compose config`, `up --wait` до healthy, `psql` по обеим базам, цикл `down`/`up`, полный сброс) распределены по P03–P07 и сводятся в `result.md`.

Отдельно фиксируется в `result.md`: обязательный набор **не приобретает зависимости от Docker** — полный локальный прогон на машине без Docker остаётся возможным, job `compose` изолирован от job `checks`.

## Блокеры и открытые вопросы

- **P01 — установка ПО на хост.** Провайдер согласован владельцем 2026-08-16 (colima + `docker` CLI + Compose plugin через Homebrew). До завершения P01 пункты P03–P07 заблокированы; если установка не состоится, они фиксируются в `result.md` как невыполненные, а не обходятся.
- Форма строки подключения для `back/002` (`DATABASE_URL` целиком или набор переменных) этой задачей не определяется — решение за `back/002`.
- PostgreSQL 19 выходит в сентябре 2026. Контур закрепляет мажор 18; переход — отдельное решение с `pg_upgrade` или dump/restore. Не блокер, но известное следствие.
