# Результат infra/009

## Итог

Приложение упаковано в один Docker-образ: multi-stage `Dockerfile` в корне репозитория собирает
два web-бандла клиента и рантайм-слой с API; контейнер стартует сам, слушает порт из `PORT`
и отдаёт с одного порта гостевой клиент (`/`), владельческий (`/admin`) и операции контракта.
Введён флаг `SEED_DEMO` (демо-календарь на старте) и слой команд `image-build`/`image-run`.
Все пункты P01–P10 выполнены. Приложение опубликовано на DockHost:
<https://6b1y-3d3v-dk6o.gw-1a.dockhost.net> (гость на `/`, владелец на `/admin`), сквозной
сценарий проверен вручную на публичной ссылке, `SEED_DEMO` включён после проверки.

## Что изменено

- **Клиент** (P01, P02): `resolveApiBaseUrl()` понимает маркер `same-origin` (пустой `baseUrl` —
  запросы на origin страницы); дев-дефолты `localhost:4010`/`10.0.2.2:4010` перестали быть
  экспортами и живут только в `__DEV__`-ветке — в production-бандл не попадают (AC4), незаданная
  переменная в production — явная ошибка. Новый `app.config.ts` — базовый префикс web-экспорта
  из `EXPO_WEB_BASE_URL` (владельческий бандл живёт под `/admin`).
- **API** (P03–P05): флаг `SEED_DEMO` в `config.ts` (дисциплина «мусор → отказ старта»);
  демо-сид `bootstrap/seed.ts` — наполнение через use-cases (`completeAdminSetup`,
  `createAdminEventType`), вызов из `server.ts` только при включённом флаге; `createApp` получил
  второй аргумент с каталогами web-бандлов, `express.static` смонтирован между циклом `ROUTES`
  и `notFoundHandler` (guest на `/`, owner на `/admin`), реестр `ROUTES` не тронут; `server.ts`
  передаёт конвенционные пути `apps/client/dist/{guest,owner}`, вычисленные от файла, только
  когда оба каталога существуют.
- **Образ** (P06): корневые `Dockerfile` (multi-stage на `node:26-slim`; build — полный `npm ci`
  и два `expo export --clear` с разными `EXPO_PUBLIC_APP_MODE`; runtime — только манифесты
  цепочки API, `npm ci --omit=dev -w apps/api` с сохранением симлинков workspaces, исходники без
  транспиляции, `USER node`) и `.dockerignore`.
- **Слой команд и гейт** (P07): цели `image-build`/`image-run` в `infra/Makefile`, одноимённые
  делегаты в корневом `Makefile`; `scripts/lint-docs` дополнен паттернами `docker build` и
  `docker run`; `infra/AGENTS.md` уточнил принадлежность делегатов зоне.
- **Правки код-ревью** (5 коммитов после P08): отказ сида в конвенции старта (`MiniCal API: demo
  seed failed — …` + exit 1) вместо сырого unhandled rejection; graceful shutdown по
  `SIGTERM`/`SIGINT` (node — PID 1 контейнера, `docker stop` теперь 0.2 с вместо таймаута);
  `Cache-Control: immutable` для хешированных ассетов (html остаётся `max-age=0`); строгий
  `parsePort` (`^\d+$` — `0x10`/`1e3`/`+3001` отвергаются); build-time проверки в
  `app.config.ts` — production-экспорт без `EXPO_PUBLIC_API_BASE_URL` и префикс без ведущего
  слэша валят сборку, а не посетителя; `.dockerignore` получил `**/`-формы для `.env*` и
  харнессов (зональный `.env` не утекает в бандлы), исключены тесты/доки (контекст сборки
  9.9 МБ → 2.1 МБ); `ARG NODE_VERSION` — одна запись major в Dockerfile; `image-run` — кавычки
  значений, guard «образ не собран», локальный дефолт `PUBLIC_WEB_URL=http://localhost:<PORT>`,
  контейнер `minical-<PORT>`; общий HTTP-харнесс тестов зоны api (`http/testServer.ts`) вместо
  трёх копий; синхронизированы README/AGENTS (семантика `publicUrl`, оговорка про `SEED_DEMO`
  и рестарты, `.dockerignore` в allow-list зоны, таблица переменных — ссылка вместо пересказа).
- **Документация** (P08 + добор): `infra/README.md` — разделы «Образ приложения» и «Публикация»
  (порядок Render, критерий переключения на Railway, предупреждения про `/admin` без auth и
  cold start); `docs/sources-of-truth.md` — исключение для корневых `Dockerfile`/`.dockerignore`
  и трактовка «Dockerfile — исполняемый рецепт»; `docs/architecture.md` и корневой `README.md` —
  структура и способ запуска; `apps/api/architecture.md` — две точки вставки middleware, раздача
  бандлов, требования к рантайм-образу, счётчик тестов; уточнён комментарий `publicUrl`
  в `apps/api/src/config.ts` (поле отдаётся в owner-ответах, гостям не раздаётся).

## Отклонения от brief / ADR / plan

- **Платформа публикации — DockHost вместо Render** (решение владельца 2026-08-19). Регистрация
  Render требует зарубежную банковскую карту — российские карты отключены от международного
  процессинга, шаг оплаты непроходим; запасной Railway имеет то же ограничение. Сработал критерий
  переключения ADR §7 («оплата/регистрация блокирует») до первого деплоя. DockHost закрывает все
  требования пути: сборка образа из Dockerfile git-репозитория на каждый push, переменные
  окружения, публичный HTTPS-домен; оплата поресурсная в рублях (~250 ₽/мес за минимальную
  конфигурацию). По ADR смена платформы не требует нового ADR — фиксируется здесь, порядок
  публикации в `infra/README.md` переписан на фактическую платформу. Отличие от Render, учтённое
  в инструкции: `PORT` платформа не назначает — маршрут ведёт трафик на объявленный порт
  контейнера (3001, дефолт API).
- **FR11 брифа сформулирован неточно** («backend сообщает её *гостю* в поле `publicUrl`»):
  по контракту `publicUrl` принадлежит owner-ответам настроек и гостям не отдаётся
  (`PublicCalendarResponse` несёт только `displayName`). Реализация следует контракту; суть
  требования — адрес задаётся переменной `PUBLIC_WEB_URL` на деплое — выполнена. Попутно
  исправлен вводивший в заблуждение комментарий в `config.ts`.
- **AC10-тест сервера**: строка P04 «с выключенным флагом store пуст» отдельным юнит-тестом
  не покрыта — обеспечено условием в `server.ts` (видно в диффе), тестами config на выключенные
  значения и smoke-проверкой образа в обоих положениях флага.
- Прочих отклонений нет: решения ADR §1–§8 перенесены в код дословно.

## Известные ограничения и риски

- **Данные не переживают перезапуск** (принято в brief, Р-brief-3): хранилище in-memory до
  `back/002`; с включённым сидом каждый рестарт возвращает демо-состояние.
- **Мастер онбординга недоступен при включённом сиде** (повторный setup → `409`): сценарий 2
  проверяется на пустом хранилище до включения `SEED_DEMO` — порядок закреплён в
  `infra/README.md`.
- **`/admin` публикуется без auth** — учебная среда (правило 9), защита не подразумевается.
- **Docker Hub недоступен с машины разработки** (TLS timeout до `registry-1.docker.io` и зеркал):
  базовый образ `node:26-slim` для локальной сборки вытянут через стороннее зеркало и
  перетегирован; в репозитории — канонический `FROM node:26-slim`. На платформе публикации это
  не воспроизводится (она тянет базовый образ со своей сети), но локальная сборка «с нуля»
  на этой машине требует того же обходного шага.
- **Локальный образ — arm64** (colima): платформа соберёт свой под свою архитектуру из того же
  Dockerfile.
- **Ответы отдаются без gzip/brotli**: сжатие потребовало бы новой рантайм-зависимости (NFR2
  запрещает), JS-бандл ~1.2 МБ уходит как есть; immutable-кеш смягчает это для повторных
  визитов, а прокси платформы может сжимать сам — не проверяется до P10.

## Описание для MR

### Summary

Docker-образ приложения и слой команд для его сборки и запуска (задача `infra/009`,
brief/ADR/plan согласованы). Один образ отдаёт с одного порта: гостевой web-клиент (`/`),
владельческий (`/admin`) и REST API. Контейнер стартует сам и слушает порт из `PORT`.
Приложение опубликовано на DockHost: <https://6b1y-3d3v-dk6o.gw-1a.dockhost.net> — сквозной
сценарий проверен на публичной ссылке вручную, демо-сид включён.

### Changes

- Корневые `Dockerfile` (multi-stage, `node:26-slim`: сборка двух web-бандлов с
  `EXPO_PUBLIC_API_BASE_URL=same-origin`; рантайм — только цепочка `apps/api` без
  dev-зависимостей, запуск исходников без транспиляции) и `.dockerignore`.
- Клиент: маркер `same-origin` в `resolveApiBaseUrl()`, дев-дефолты под `__DEV__` (в
  production-бандле дев-адресов нет), `app.config.ts` с `experiments.baseUrl` из
  `EXPO_WEB_BASE_URL`.
- API: флаг `SEED_DEMO` + демо-сид через use-cases; раздача статики `express.static` между
  реестром маршрутов и JSON-404 — контракт и `ROUTES` не тронуты.
- Команды: `make image-build` / `make image-run` (зона `infra/`, делегаты в корне);
  `lint-docs` дополнен паттернами `docker build`/`docker run`.
- Документация: эксплуатация и порядок публикации в `infra/README.md`; исключение для корневого
  `Dockerfile` в контракте размещения; обновлены `docs/architecture.md`,
  `apps/api/architecture.md`, README корня и зон.

### Verification

  generate-check, контрактный гейт).
- Образ: сборка из чистого контекста; smoke — `/health`, оба бандла, JSON-404, оба положения

- После merge нужно переключить ветку деплоя в DockHost на `main` (сейчас собирается из ветки
  задачи).
