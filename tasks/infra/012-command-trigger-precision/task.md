# infra/012 — Точность триггера агента: команда только с начала строки

## Контекст и цель

Issue #10. Условие job'а `comment` в `.github/workflows/opencode.yml` ищет команду оператором
`contains`, то есть подстрокой где угодно в тексте комментария:

```yaml
(contains(github.event.comment.body, '/oc') ||
 contains(github.event.comment.body, '/opencode'))
```

Агента запускает любое упоминание — цитата чужого комментария, обсуждение самой команды, путь
`.github/workflows/opencode.yml`, внутри которого лежит подстрока `/opencode`. За 2026-08-30 это
сработало дважды: агент ответил сам себе (прогон 33306960256) и завёл лишний PR. Тогда же в
`infra/010` поставили фильтр `github.event.comment.user.type != 'Bot'` — он закрыл только случай,
когда автором лишнего комментария оказывается бот, но не случай, когда человек цитирует команду
или обсуждает её.

Замер на 2026-08-31: 19 прогонов workflow по событию `issue_comment`, из 40 оценок job'а `comment`
30 пропущено, 8 успешно, 1 упал, 1 отменён. То есть агент отработал около десяти раз, и часть
этих запусков — не адресованные ему команды.

Выражения GitHub Actions регулярных выражений не поддерживают: доступны только `contains`,
`startsWith`, `endsWith`. `startsWith(body, '/oc')` не годится — он проверяет начало **всего
тела**, а команда часто стоит второй строкой после пояснения.

Трек lite: контракт и схема БД не затронуты, работа целиком в зоне `infra/` (CI configuration
принадлежит ей), новых зависимостей нет, работы меньше дня. Все пять критериев `flows/lite.md` —
«нет».

Цель: агент запускается на команду, стоящую в начале строки, и не запускается на её упоминание
внутри текста.

## Решение

Отдельный job `detect`, который делает то, чего не умеют выражения Actions, — сопоставление
с регулярным выражением, — и отдаёт результат в `needs`.

```yaml
jobs:
  detect:
    if: |
      github.event_name != 'pull_request' &&
      github.event.comment.user.type != 'Bot' &&
      (contains(github.event.comment.body, '/oc') ||
       contains(github.event.comment.body, '/opencode'))
    runs-on: ubuntu-latest
    timeout-minutes: 5
    outputs:
      command: ${{ steps.check.outputs.command }}
    permissions: {}
    steps:
      - id: check
        env:
          BODY: ${{ github.event.comment.body }}
        run: |
          if printf '%s' "$BODY" | grep -qE '^/(oc|opencode)([[:space:]]|$)'; then
            echo 'command=true' >> "$GITHUB_OUTPUT"
          else
            echo 'command=false' >> "$GITHUB_OUTPUT"
          fi

  comment:
    needs: detect
    if: needs.detect.outputs.command == 'true'
    ...
```

Четыре решения внутри, каждое со своей причиной.

**`contains` остаётся, но переезжает в `detect`.** Он больше не решает, запускать ли агента, —
он решает, стоит ли вообще поднимать раннер для разбора. Комментарии без подстроки отсеиваются
условием job'а, не тратя ничего; на оставшиеся тратится job на несколько секунд. Без этого
предфильтра `detect` поднимался бы на каждый комментарий в репозитории.

**Тело комментария передаётся через `env`, а не подстановкой в скрипт.** Если написать
`grep ... '${{ github.event.comment.body }}'`, текст комментария попадёт в исполняемый скрипт
буквально, и любой пользователь GitHub сможет выполнить произвольную команду на раннере
закрывающей кавычкой. Через `env` тело остаётся данными: оболочка получает его как значение
переменной, а не как часть команды. Это единственное место задачи, где цена ошибки — не лишний
запуск, а исполнение чужого кода.

**Регулярное выражение — `^/(oc|opencode)([[:space:]]|$)`.** `^` без ведущих пробелов: команда
стоит в первой позиции строки, отступ в четыре пробела — это markdown-блок кода, то есть
цитирование, а не команда. `grep` работает построчно, поэтому команда во второй или пятой строке
комментария засчитывается — так люди и пишут, сначала пояснение, потом команда. Хвостовое
`([[:space:]]|$)` отсекает `/opencode.yml`: после имени команды обязан быть пробел или конец
строки. `[[:space:]]` покрывает и `\r`, если тело придёт с CRLF.

**У `detect` нулевые права — `permissions: {}`.** Job не делает ни checkout, ни обмена OIDC,
ни единого обращения к API: ему не нужно ничего, и это тот случай, когда «минимально
необходимое» буквально пусто. Дефолт репозитория и так `read`, но полагаться на настройку,
которую меняют не в этом файле, незачем.

**Строковое сравнение `== 'true'`.** Выходы job'ов в Actions — всегда строки; `needs.detect.outputs.command`
никогда не булев, поэтому сравнение только со строкой.

Что задача **не** делает: это патч точности, а не безопасности. Команда, намеренно написанная
с начала строки, по-прежнему доступна любому пользователю GitHub и по-прежнему становится
промптом агента. Настоящее закрытие — фильтр `author_association == 'OWNER'`, который в
`infra/010` сознательно не ставили, и связка «платная модель обязана вернуть фильтр» остаётся
в силе.

Отвергнутая альтернатива: **`startsWith(body, '/oc')`** — не требует отдельного job'а, но
проверяет начало всего тела и ломает обычный способ писать команду после пояснения.

## Результат и проверки

Триггер сужен до команды в начале строки. Дефект, из-за которого агент запускался на упоминание
команды в тексте, закрыт; фильтр ботов из `infra/010` сохранён и теперь работает раньше — до
разбора тела.

### Проверка регулярного выражения (P02)

Тот же `grep -qE '^/(oc|opencode)([[:space:]]|$)'` прогнан на десяти формах:

| Тело комментария | Результат |
|---|---|
| `/oc explain this issue` | срабатывает |
| пояснение, затем `/oc review this` второй строкой | срабатывает |
| `/oc` без аргументов | срабатывает |
| `/opencode review` | срабатывает |
| тело с CRLF и командой | срабатывает |
| `я написал /oc в комментарии` | пропуск |
| `> /oc explain this issue` — цитата | пропуск |
| `смотри .github/workflows/opencode.yml` | пропуск |
| `/opencode.yml лежит в .github` | пропуск |
| `    /oc explain` — отступ markdown-блока | пропуск |

Формулировка пункта чеклиста при этом оказалась неточной и исправлена: в исходной редакции стояло
«совпадение только у первых трёх», тогда как вариант с CRLF обязан совпадать — хвостовое
`[[:space:]]` для того и добавлено, чтобы `\r` считался разделителем.

### Проверка в GitHub (P03)

Три контролируемых случая на тестовом issue #4, все после merge:

| Прогон | Комментарий | `detect` | `comment` |
|---|---|---|---|
| 33352829896 | `/oc` с начала строки | success | **success** — агент ответил по существу |
| 33352836946 | `/oc` в середине строки | success | **skipped** |
| 33352869653 | ответ самого агента | **skipped** | skipped |

Второй случай — ровно то, ради чего задача заводилась: до правки `contains` запустил бы агента
на этом тексте. Третий показывает, что фильтр ботов срабатывает раньше разбора и раннер под grep
не поднимается вовсе.

Пример старого поведения остался в истории для сравнения: прогон 33352812986 шёл на коммите
`e9334a7`, где job `detect` ещё не существовало, и job `comment` на нём отработал.

### Замечания авто-ревью на PR #18

Из четырёх замечаний два сняты фактами, одно оказалось неточным, одно принято.

**«`REGISTRY.md` правился руками»** — нет: файл сгенерирован `scripts/task registry`, и это
проверяется командой `scripts/task registry --check`, отвечающей «REGISTRY.md актуален».
Отличить генерат от ручной правки по диффу нельзя в принципе, поэтому проверять надо не диффом.

**«Гейт согласован без `task approve`»** — согласован именно командой, после явного указания
владельца закрыть задачу. Признак проверяемый: `checksum` гейта считается от текста `task.md`
до маркера `## Чеклист`, `meta.selfHash` — от манифеста; подстановка статуса руками
рассинхронизировала бы обе величины и уронила `scripts/task check`.

**«Самозапуск через `pull_request_review_comment`»** — неточность в посылке. В этом событии
`github.event.comment.body` содержит только текст, написанный человеком; контекст диффа лежит
в `diff_hunk` и `path` и в условие не попадает, поэтому «путь файла из диффа проходит предфильтр»
не воспроизводится. Остаётся намеренное поведение: `/oc` с начала строки в комментарии к строке
кода вызывает агента — ради этого подписка и заведена.

**«PR заявляет закрытие issue авансом»** — принято, формулировка была преждевременной.

### Гейты (P04)

`make gates` из корня — exit 0, включая `scripts/task check` (27 задач, 0 ошибок) и `lint-docs`.

### Что осталось за рамками

- **Фильтр по автору** (`author_association == 'OWNER'`) — не ставится, решение владельца из
  `infra/010`. Связка «переход на платную модель обязан вернуть фильтр» остаётся в силе.
- **Закрепление стороннего action по SHA** — `infra/011`, до сих пор стаб.
- **`concurrency` у `opencode.yml`** — очередь комментариев по-прежнему может запустить несколько
  агентов параллельно. Замечено при этом аудите, отдельной задачей.

### Итог

Агент запускается на команду и не запускается на разговор о ней. Патч закрывает точность, а не
безопасность: намеренная команда с начала строки по-прежнему доступна любому пользователю GitHub
и по-прежнему становится промптом.
