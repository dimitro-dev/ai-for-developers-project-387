# front/ui/003 — Owner uispec sync

## Контекст и цель

Owner-спеки кита (экраны `01–11`, все `approved`) написаны до закрытия GAP-002 контрактом 0.2.0
(задача `contract/001`) и до появления макетов недостающих экранов. 2026-08-17 владелец добавил
доски `owner-mobile-settings.png` (экран 08, три состояния) и `owner-mobile-settings-details.png`
(экраны 09, 10, 06, 11 — восемь кадров). Перед реализацией `front/owner/001` спеки нужно привести
к актуальному контракту, принятым решениям и новым макетам, чтобы реализующий агент строил экраны
по букве спек без «осознанных отходов».

Решения владельца из сессии проработки `front/owner/001` (2026-08-17):

- bottom-sheets 04 и 11 — локальные компоненты родительских экранов, а не route навигации;
  данные передаются пропсами (интервал для префилла; `BookingView` из списка встреч);
- `eventTypeTitle` берётся из `Booking.eventTypeName` (контракт 0.2.0), client-side join
  по словарю типов удаляется — GAP-002 в спеках снимается;
- решение FR4 путь (б) `contract/001` остаётся в силе: иконка типа события едина для всех,
  различие — только акцентным цветом из `id`; разные глифы на новом макете — вольность
  отрисовки, спека фиксирует единый глиф;
- расхождения макетов со спеками решаются в пользу макетов (SettingsRow с иконками,
  error-состояние экрана 08, длительность чипами, баннер ошибки создания, состав
  EventTypeCard, оформление деталей встречи, timezone-пикер как sheet с поиском).

## Решение

Правки только в `docs/ui-spec-kit/` (Markdown и XML), код приложений не трогается; синхронизация
`apps/client` с изменёнными токенами и спеками — работа `front/owner/001`. Обоснование трека lite:
все пять критериев «нет» — контракт и generated не меняются, БД нет, зона одна (`docs/ui-spec-kit`),
архитектурных решений в коде нет (решения зафиксированы выше и в спеках), объём — часы.

Каждая изменённая спека проходит короткий ревью отдельным агентом (соответствие макету, контракту
0.2.0, решениям выше, валидатору V1–V11); финальная проверка — `npm run uispec:validate` и корневой
`npm test`.

## Результат и проверки

### Итог

Все 7 пунктов выполнены двумя параллельными агентами (зоны: «sheets+GAP-002» и «макеты+токен»),
затем пять независимых ревью по кластерам (рабочие часы, встречи, настройки, типы событий,
сквозные файлы): два чистых, 13 находок (2 блокера, 5 важных, 6 мелких) — все исправлены.
Изменения только в `docs/ui-spec-kit/` (локальная рабочая копия, вне git); в git — только
документы задачи.

Ключевые результаты:

- **Конвенция sheet-компонента** зафиксирована в `MANUAL.md` §2.1 (спека без route: `Meta
  presentation/parent`, блок `Props`, открытие `local.update`+`onSuccessState`, закрытие
  `local.transition` / `local.submit result="close"`, перенос payload sheet→родитель); экраны
  03/04/05/07/11 переведены на неё, оба route удалены из `navigation.uispec.xml`.
- **GAP-002 вычищен из спек**: `eventTypeTitle` — `from="Booking.eventTypeName"`, action и
  биндинг `loadMeetingsEventTypes` удалены; view-model экрана 05 — из двух операций.
- **Спеки 06/08/09/10 синхронизированы с досками** `owner-mobile-settings.png` и
  `owner-mobile-settings-details.png`: иконки SettingsRow, error-состояние 08, timezone-пикер
  `pickerMode="bottom-sheet"` с поиском, saving «Сохраняем…», чипы длительности (новый компонент
  `duration-selector` + registry), баннер `InlineAlert` (компонент переведён в approved),
  состав `EventTypeCard` (единый глиф — FR4 путь (б), примечание о вольности макета),
  `FRAME_MAP.md`/`ASSETS.md`/frontmatter reference обновлены.
- **Новые компонентные спеки**: `confirmation-dialog` (approved), `duration-selector` (approved);
  `settings-row` получил ведущую иконку; `schedule-card`/`meeting-card` — контракт нагрузки
  onPress (`interval`/`booking`).
- **Токены dark-темы**: `color.action.primary` #4D86FF → #246BFD (контраст к белой подписи
  3.40 → 4.57 ≥ AA), `color.action.primaryPressed` #6A99FF → #1554D6 (2.76 → 6.42); пересчёт
  задокументирован в `colors.tokens.xml`, независимо перепроверен ревью; light не менялась.
- Исправления по ревью: `Payload` у `confirmOverwriteApply` (04), `id="schedule-list"` (03/07),
  таб-бар и канал ошибок экрана 09 (`BottomNavigation`, `$state.message`, `fieldErrors` +
  `error=`), дефолт длительности 30 и снятие задвоения ошибки поля (10), `goBack` (06),
  kebab-ключи `fieldError()` в 02, докстрока `formatAvailabilitySummary`.

### Известные ограничения

- Синхронизация `apps/client/src/design-system/tokens.ts` с новыми значениями токенов —
  пункт P03 плана `front/owner/001` (клиент до неё несёт старые значения).
- Генератор каркасов не собирает sheet-спеки без route (имена файлов с числовым префиксом) —
  sheets реализуются вручную внутри родителя (MANUAL §2.1).
- Lint-подсказки о литералах 208/176 (08 + два гостевых файла) оставлены — кандидат в токен
  `size.illustration.*`, отдельной задачей.
- Наблюдение ревью: dark `color.border.focus` #6A99FF и `color.accent.1` #4D86FF корректны в
  своих ролях (порог 3:1), но при смене роли потребуют пересчёта.
