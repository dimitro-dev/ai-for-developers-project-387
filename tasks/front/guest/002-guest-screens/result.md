# Результат TASK-front-guest-002

## Итог

Гостевой сценарий реализован в `apps/client` целиком по четырём спекам `front-ui-002`
(каталог встреч, выбор даты и времени, данные гостя, подтверждение) на фундаменте
`front-guest-001` и подтверждён сквозными прогонами на web и Android-эмуляторе против реального
API `back-001`, включая конфликт слота (кадр 8) и повтор после обрыва сети (кадр 9).

Работа велась в изолированном worktree `../ai-for-developers-project-386-front-guest-002` на ветке
`task/front-guest-002-guest-screens`; основное дерево оставалось на `main`. Ветка запушена и
открыт [MR #7](https://github.com/dimitro-dev/ai-for-developers-project-386/pull/7) — по прямому
указанию пользователя 2026-08-15 (до этого действовало правило плана «push только после явного
ОК»). Каталоги AI-процесса
(`docs/`, `tasks/`, `.opencode/`, `CLAUDE.md`, `.mcp.json`) проброшены в worktree симлинками —
единый источник без копий; их имена добавлены в локальный `.git/info/exclude`, потому что
`.gitignore` ловит эти пути только как каталоги, а симлинк каталогом не является.

Экраны P10–P12 реализованы параллельными агентами в том же worktree (по указанию пользователя),
общий каркас (`GuestStack`, дизайн-система, helpers, гейты, сквозные прогоны) — основной сессией.

## Отклонения от brief / ADR / plan

1. **Глиф `event-type`** (открытый вопрос 1 плана) — MaterialCommunityIcons `forum`. Выбран по
   кадрам 1–7 `guest-mobile-flow.png`: на макете это парный речевой пузырь, а не `grid`/`tag`/
   `shape-outline` из списка кандидатов ADR §6. Второй override остался как в ADR:
   `calendar-x` → MCI `calendar-remove`.
2. **Helpers `@/shared/datetime` принимают timezone явным параметром**, тогда как сигнатуры в
   `components.registry.xml` его не содержат (`dateLabel(atUtc)`). Это прямое требование ADR §8
   («тестируемость не зависит от TZ окружения»); в спеках вызовы остаются одноаргументными, их
   резолвит экран, подставляя `guestTimeZone()`. Пути импорта модулей — как в registry (AC6).
3. **`AppButton` получил вариант `text`** — его требует разметка `booking-summary-card`
   (`Button variant="text" label="Изменить"`), а спека `primary-button` описывает только
   `primary`. Расширение дизайн-системы под существующую спеку, не новая сущность.
4. **Ключ идемпотентности в `GuestFlowProvider`, а не в состоянии экрана формы.** Спека 14 держит
   `bookingKey` свойством состояния; ADR §2 оставляет в локальном state только машину,
   `fieldErrors` и `message`. Наблюдаемое поведение то же (ключ живёт монтирование формы).
5. **Вход на экран подтверждения — `navigation.reset`** (уточнение плана P12 к ADR §4): push
   оставил бы системное «назад» в форму созданной брони и нарушил FR4.4/AC4.
6. **`popTo` выполняется через `StackActions`, а не `navigation.popTo('GuestSlots')`.** Типы
   React Navigation требуют от метода полный набор обязательных параметров route слотов, а форма
   получает лишь часть их (`durationMinutes` и `eventTypeDescription` ей не передаются).
   `navigation.dispatch(StackActions.popTo('GuestSlots', undefined, { merge: true }))` выражает
   ту же цель ADR §4; `merge: true` обязателен — без него редьюсер `POP_TO` перезаписал бы
   параметры существующего экрана слотов значениями `initialParams`.
7. **`AppSafeArea` добавлен в дизайн-систему** — тег `SafeArea` числится в
   `components.registry.xml`, но в фундаменте реализован не был; без него `Viewport
   safeArea="true"` спеков не исполняется (найдено живым прогоном на Android).
8. **Заголовок каталога зависит от падежа `displayName`.** Спека задаёт шаблон
   «Запланировать встречу с {displayName}», поэтому при `displayName = "Дмитрий"` выходит
   «с Дмитрий». Это свойство шаблона спеки и данных владельца, а не дефект реализации;
   изменение формулировки — вопрос к задаче `front-ui`.

## Известные ограничения и риски

1. Сгенерированные типы состояний перенесены разово: при изменении спек 12–15 перенос повторяется
   вручную, и четыре расхождения генератора из `generation-report.md` воспроизведутся снова.
2. Иллюстрация `$asset.network-error` (кадр 9) отсутствует в пакете — на экране placeholder с
   пометкой `TODO-ASSET` (санкция brief FR3.7).
3. `GAP-004` остаётся открытым: серверная ошибка валидации показывается общим сообщением, без
   подсветки конкретного поля.
4. Шрифты двух icon-семейств (Feather, MaterialCommunityIcons) попадают в web-бандл
   (≈ 56 КБ + 1.3 МБ ttf).
5. **`accessibilityState.selected` на web не превращается в `aria-selected`**: react-native-web
   не выставляет этот атрибут для `role="button"` (ARIA его там не допускает). На Android состояние
   передаётся системе штатно, в тестах проверяется через props. Выбор кодируется ещё и заливкой,
   поэтому требование «не только цветом» на Android выполнено, а на web — частично.
6. Выбор слота живёт в локальном состоянии экрана: после выгрузки процесса гость выбирает заново.
7. Черновик гостя не очищается после успешной брони (спека очистки не требует) — следующая бронь
   в том же сеансе открывает форму с прежними значениями.

## Описание для MR

### Summary

Гостевой сценарий MiniCal целиком: каталог встреч, выбор даты и времени, форма гостя и
подтверждение — по спекам `front-ui-002` на фундаменте `front-guest-001`. Сценарий подтверждён
сквозными прогонами на web и Android-эмуляторе против реального API, включая конфликт слота и
идемпотентный повтор после обрыва сети.

### Changes

- четыре экрана: контейнер + чистый view + чистый редьюсер на каждом, generated-типы состояний
  перенесены из UISpec-кита; стаб-экраны фундамента удалены;
- восемь компонентов спеков (`DateChip`, `DateStrip`, `SlotItem`, `SlotGrid`, `InlineAlert`,
  `PublicEventTypeCard`, `BookingSummaryCard`, `ConfirmationDetails`);
- helpers по `components.registry.xml`: даты и время, слоты, типы встреч, валидация формы;
- `AppIcon` переведён на `@expo/vector-icons` (реальные глифы вместо плейсхолдера),
  `AppButton` получил вариант `text`, появились `AppSafeArea` и константы адаптива;
- ключ идемпотентности выдаётся заново на каждое монтирование формы (семантика спеки 14).

### Verification

`contracts:format:check`, `generate:check`, `typecheck`, `npm test`, `uispec:validate`,
`npm test -w @minical/api`, `npm test -w @minical/client` (23 сьюта, 192 теста),
`expo export --platform web` — все зелёные. Плюс два ручных сквозных протокола (web и Android)
против `back-001`: основной путь, кадр 8 и кадр 9, по одной брони на слот.

### Known limitations

Иллюстрация кадра 9 — placeholder `TODO-ASSET`; `GAP-004` открыт (серверная ошибка валидации
показывается общим сообщением); на web `accessibilityState.selected` не даёт `aria-selected`;
в бандл попадают шрифты двух icon-семейств.
