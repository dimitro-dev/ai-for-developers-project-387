# process/002 — REGISTRY: очередь без завершённых, история отдельно

## Контекст и цель

Секция «Очередь работ» в генерируемом `tasks/REGISTRY.md` смешивает завершённые задачи (9 строк)
с предстоящими (5 строк) — очередь перестала отвечать на вопрос «что дальше» (замечание владельца
2026-08-16). Колонка «Почему здесь» названа невнятно. Попутно новый инструмент подсветил два
огреха данных, унаследованных от ручного процесса: у `infra/006` пункт P10 не переведён в
«завершено», хотя де-факто выполнен 2026-08-15 (result согласован, реестр обновлялся), а
rationale `process/001` написан в настоящем времени («Активная задача…») и устарел.

Цель: очередь показывает только незавершённые задачи; нарратив выполненных сохраняется отдельной
подсекцией; данные приведены в соответствие фактам.

Трек lite — обоснование: правка одной зоны (`tasks/tools/` + данные задач), без контракта, БД и
архитектурных решений, объём ~час.

## Решение

1. `tasks/tools/lib/registry.ts`: секция «Очередь работ» — только задачи со стадией ≠ «завершена»
   (топологический порядок по `queue.after` сохраняется); ниже подсекция `### История выполнения`
   с завершёнными задачами очереди в том же формате; колонка «Почему здесь» в обеих таблицах
   переименовывается в «Обоснование». Детерминизм генерации сохраняется.
2. Тесты `tasks/tools/tests/` обновляются под новый формат (разделение секций, переименование
   колонки, задача без завершённых / без незавершённых — обе таблицы корректны и при пустоте).
3. Данные: состояние P10 в `tasks/infra/006-ci-release-please/plan.md` → «завершено — де-факто
   выполнено 2026-08-15 (result согласован, реестр обновлён); состояние не было переведено в
   старом процессе»; `task set process/001 queue.rationale` — формулировка в прошедшем времени.
4. `task registry` перегенерирован, `task check` зелёный.

## Результат и проверки

Сделано:

- `tasks/tools/lib/registry.ts`: секция «Очередь работ» рендерит только задачи со стадией ≠ «завершена»
  (фильтр после топологической сортировки — порядок оставшихся не меняется), завершённые ушли в подсекцию
  `### История выполнения` с той же таблицей; колонка «Почему здесь» → «Обоснование» в обеих таблицах;
  вводная строка переписана. Пустая очередь без участников — как раньше, строка «Очередь пуста.»;
  очередь без незавершённых — «Очередь пуста.» плюс история; без завершённых подсекция не печатается.
  Счётчик `в очереди` в выводе команды теперь считает незавершённые.
- `tasks/tools/tests/registry.test.ts`: helper секции стал уровнеосознанным (подсекция не обрывает секцию),
  добавлены кейсы «завершённая уходит в историю», «без завершённых подсекции нет», «завершены все —
  очередь пуста, история хранит порядок»; проверка имени колонки «Обоснование».
- Данные: состояние P10 в `tasks/infra/006-ci-release-please/plan.md` переведено в «завершено» с пометкой
  о де-факто выполнении 2026-08-15 (задача в реестре стала 10/10); `queue.rationale` у `process/001`
  переписан в прошедшем времени через `npm run task -- set` (rev 9).
