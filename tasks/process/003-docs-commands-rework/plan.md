## Порядок и зависимости

Порядок обусловлен требованием ADR: репозиторий остаётся рабочим на каждом шаге, а промежуточное состояние с двумя живыми входами не выносится в `main` как результат.

| Пункт | Зависит от | Почему |
|---|---|---|
| P01 | — | каркас; на цели ссылается вся последующая документация |
| P02 | P01 | цель `task-check` живёт в корневом `Makefile` |
| P03 | P01 | инвариант (б) сверяет упоминания с существующими целями |
| P04 | — | независим; выполняется до любого переноса в `docs/` |
| P05 | P01, P04 | описывает `Makefile` как дом команд, правится файл внутри `docs/` |
| P06 | P04, P05 | принимающий документ должен быть в git, контракт — записан |
| P07–P10 | P03, P06 | отчёт `lint-docs` — рабочий список; корневой файл задаёт образец |
| P11 | P04 | правит только содержимое `docs/` |
| P12 | P01 | CI зовёт цели |
| P13 | P01, P02 | скиллы зовут `scripts/task` и цели |
| P14 | P12, P13 | очистка манифестов ломает старый вход — переводить последними тех, кто им пользуется |
| P15 | все | включение гейта и фаза «Проверка» |

- **P01 первый** — каркас, на который опираются все ссылки на цели в документации.
- **P03 рано, но без включения в гейты** — отчёт `lint-docs` служит рабочим списком для P06–P11; включение в `gates` — только в P15, иначе гейт красный всю задачу.
- **P04 до P05–P06** — переносить содержимое в `docs/` до того, как каталог войдёт в git, значит потерять его из клона на время задачи.
- **P14 предпоследний** — очистка манифестов ломает старый вход, поэтому выполняется после того, как на новый переведены CI (P12) и скиллы (P13).
- **P15 последний** — включает гейт и проходит фазу «Проверка».

Коммит на пункт плана; после каждого пункта прогоняются гейты затронутой области, полный набор — в P15.

Полный список — в корневом `AGENTS.md`, результаты фиксируются в `result.md`.

- [ ] клиентский гейт — аналогично для `apps/client`
- [ ] `lint-docs` — новая проверка, включается в набор в P15
- [ ] тесты и типы CLI задач — обязательны из-за правки `tasks/tools/task.ts` в P02

## Блокеры и открытые вопросы

- **Согласование гейтов дано авансом.** Владелец 2026-08-18 дал предварительное согласие на все гейты этой задачи до `plan` включительно при условии, что каждый документ проходит ревью на корректность перед согласованием. Условие выполнено: brief и ADR проверены, найденные дефекты исправлены до `approve` (в том числе возврат brief в черновик по правилу 8 из-за противоречия с Р3/Р4). Гейт `result` этим согласием не покрыт — реализация выполняется отдельной сессией и принимается владельцем обычным порядком.
- **Непрозрачность авточекера Hexlet.** Требования `hexlet/project-action` к репозиторию из его конфигурации не видны. Удерживается сохранением корневого `npm test` (FR5) и запретом трогать файлы Hexlet (NFR3). Если после push чек Hexlet покраснеет, причина ищется в первую очередь здесь.
- **Объём переноса в P07–P10.** Основной риск задачи — потеря знания, добытого отладкой (повадки Prism, `--clear`, порядок middleware, strip-only). Списки переносимых блоков зафиксированы в пунктах; сверка по ним — часть проверки каждого пункта, а не финального прогона.
- **`apps/client/architecture.md` может не понадобиться.** Решается внутри P08 по результату сверки с `docs/ui-spec-kit/MANUAL.md`: если зонального содержимого не остаётся, файл не заводится. Это не отклонение от FR11 — он требует заводить файл только при наличии содержимого.
