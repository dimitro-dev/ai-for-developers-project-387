# Результат process/003

## Итог

Введены два слоя владения: исполняемый для команд и декларативный для содержимого документации.

Команда определена ровно один раз — рецептом цели в `Makefile`: корневой владеет операциями уровня
репозитория и фан-аутом, семь зональных — глаголами своих зон, общее вынесено в `make/common.mk`.
Секции `scripts` в шести `package.json` очищены; осталась одна запись — корневой `"test": "make test"`
как страховка для непрозрачного авточекера Hexlet. CLI задач получил собственный исполняемый вход
`scripts/task`, не проходящий через `make`.

`docs/` внесён в git (73 файла, 5,2 МБ). Контракт размещения записан в `docs/sources-of-truth.md`:
у каждого вида содержимого один дом, повторное упоминание — ссылка. По этому контракту разведены
корневой `AGENTS.md` (255 → 118 строк), корневой `README.md` (192 → 68), `apps/api/AGENTS.md`
(208 → 72) и `apps/client/AGENTS.md` (125 → 97); выселенное принято четырьмя новыми файлами зон.
Ролевых формулировок «Зона X Agent» не осталось. Возврат дублирования ловит новый гейт
`make lint-docs`, включённый в `make gates` и в CI.

Все 15 пунктов плана завершены.

### Найдено при проверке: PATH и fast path GNU Make 3.81

Проверка AC15 вскрыла дефект, невидимый через `make gates`: прямой вызов `make -C apps/api typecheck`
падал с `tsc: No such file or directory` в пяти зонах из семи. Причина — GNU Make 3.81 исполняет
простой рецепт (без метасимволов shell) сама, минуя shell, и ищет программу в `PATH`, который
унаследовала при старте; `export PATH` из `make/common.mk` на этот поиск не влияет. Через `gates`
дефект не проявлялся: там всегда рекурсивный `$(MAKE)`, и дочерний процесс получает исправленный
`PATH` уже в своём окружении.

Проверено экспериментом на пяти формах рецепта: любая форма с метасимволом или префиксом `env`
находит `tsc`, голая — нет. Введён префикс `RUN := env` в `make/common.mk`; им помечены вызовы
инструментов из `node_modules/.bin` (`tsc`, `jest`, `tsp`, `expo`, `openapi-ts`, `prism`).
`node`, `git`, `docker` и `python3` берутся из системного `PATH` и префикса не требуют.
После правки все 21 сочетание «зона × глагол» (`typecheck`/`test`/`gates` в семи зонах) проходят
прямым вызовом.

### Обоснование исключения в `package.json` (FR5)

Корневой `"test": "make test"` сохранён потому, что авточекер Hexlet (`hexlet-check.yml`) исполняет
закрытый бандл, и его требования к репозиторию из конфигурации не видны. Единственный способ
удержать риск — оставить привычный вход `npm test`, делегировав его цели. Причина зафиксирована
верхнеуровневым ключом `"//"`: JSON комментариев не имеет, ключ штатно игнорируется npm, читается
через `npm pkg get '//'` и переживает запись версии release-please. Ключ-комментарий внутри секции
`scripts` для этого непригоден — `npm run` печатает его в списке доступных скриптов как настоящий.

## Отклонения от brief / ADR / plan

- **Область P02 расширена.** План называл одну строку справки в `tasks/tools/task.ts`. Фактически
  переведены все собственные сообщения CLI (34 вхождения в `task.ts`, `lib/**`, тестах) и живые
  документы процесса — `tasks/AGENTS.md`, `tasks/flows/full.md`, `tasks/flows/lite.md`,
  `tasks/_template/full/plan.md`. Причина: после P14 `npm run task -- …` перестаёт существовать, и
  каждое такое сообщение учило бы неработающей команде. NFR4 («`tasks/**` не переписывается»)
  относится к историческому протоколу завершённых задач — они не тронуты.
- **`scripts/lint-docs` написан на JavaScript, а не на TypeScript со strip-types.** План называл
  `--experimental-strip-types`; Node определяет режим по расширению файла, а имя `scripts/lint-docs`
  (без расширения, по образцу `scripts/task`) под него не подпадает. Существенное требование —
  «без новых зависимостей» — выполнено.
- **Цели `generate` у generated-пакетов нет.** План допускал зональные глаголы; фактически
  `openapi-ts` читает конфиг с путями от корня репозитория, поэтому обе строки генерации остались
  в корневом `Makefile`, а зоны `packages/api-client` и `packages/backend-contract` определяют только
  обязательный набор. Изменение конфигов ради переноса означало бы риск дрейфа generated.
- **Порядок коммитов P07–P11 не совпал с порядком плана.** Пункты выполнялись параллельно
  изолированными агентами по непересекающимся файлам; зависимость «P07–P10 после P06» соблюдена
  по содержанию (контракт зоны и словарь целей были зафиксированы до старта), но не по времени.
- **Часть правок P11 попала в коммит P04.** `docs/` вносился в git в тот момент, когда правки
  дублей в `domain-model.md` и `contract-pipeline.md` уже были на диске; отдельного diff по ним нет,
  поскольку до P04 каталог не отслеживался. Итоговое состояние проверено вручную и описано
  в таблице устранённых дублей выше.

## Известные ограничения и риски

- **`npm run <X>` больше не работает** — по решению Р1 сознательно. Отказ громкий: npm печатает
  «Missing script» и список доступных скриптов.
- **Появилась зависимость от `make`.** На macOS и Linux он есть из коробки; Windows вне
  поддерживаемых платформ проекта.
- **Совместимость с GNU Make 3.81** ограничивает рецепты: без `.ONESHELL`, `undefine`, `::=`,
  многошаговые рецепты — через `&&` или `$(MAKE)`.
- **Авточекер Hexlet непрозрачен.** Если после push его чек покраснеет, причину искать здесь: вход
  `npm test` сохранён, но теперь он проходит через `make`.
- **`lint-docs` не покрывает `.opencode/` и `tasks/**`** — первое вне git, второе исключено
  осознанно (исторический протокол). Скиллы проверяются вручную.
- **Разовый флак в `apps/api/src/http/security.test.ts`.** При независимой перепроверке один из
  двадцати одного прогона упал: тест поднимает сервер на `listen(0)` (wildcard-адрес), а запрос шлёт
  на `127.0.0.1:<порт>` — если посторонний процесс уже слушает этот порт именно на `127.0.0.1`,
  ответ приходит от него (в тот раз пришёл SSH-баннер). Три повтора подряд зелёные. Дефект
  существовал до этой задачи и её изменениями не вызван; починка — отдельной задачей backend-зоны,
  здесь не выполняется (Non-goals: новые тесты приложений задача не пишет).
- **`lint-docs` ловит только перечисленные в FR17 инструменты** (`npm run`, `npm test`, `npm ci`,
  `npx`, `docker compose`, `node --`, `tsc --`, `jest`) и сравнивает подстроки, без разбора
  Markdown. Прямой вызов `./gradlew` в `apps/client/README.md` он не считает нарушением, а слово
  «jest » в прозе счёл бы им. Расширение списка — отдельная задача: сейчас он дословно повторяет
  требование и проверяется тем же `grep`, что и AC3.
- **Подсказки CLI задач печатают `scripts/task <команда>` — путь от корня репозитория.** Из
  подкаталога такую строку скопировать напрямую нельзя (`npm run task --` работал отовсюду, потому
  что npm сам поднимался к корню workspace). Что вход живёт в корне, сказано в `tasks/AGENTS.md`.
- **Битые ссылки в документах завершённых задач** (`tasks/**`) остались: 16 ссылок ведут на
  `.opencode/agents/*` дотиповой эпохи. NFR4 запрещает их переписывать; на живую документацию это
  не влияет.

## Описание для MR

### Summary

Команды переезжают из `package.json` в `Makefile`, документация — по контракту размещения.
Каждая команда определена один раз рецептом цели; каждый факт документации имеет один дом,
остальные упоминания — ссылки. Возврат дублирования ловит новый гейт `make lint-docs`.

- `make/common.mk`, корневой `Makefile` и `Makefile` семи зон; единый словарь глаголов
  `typecheck` / `test` / `gates` во всех зонах.
