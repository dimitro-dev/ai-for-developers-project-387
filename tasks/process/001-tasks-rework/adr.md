# Architecture decision — TASK-process-001

## Контекст

Архитектура решения выработана и согласована посекционно на brainstorming-сессии 2026-08-15 —
зафиксирована в [design.md](design.md). Этот ADR не пересказывает её, а фиксирует решение ей
следовать плюс уточнения по итогам ресёрча кодовой базы (три субагента: инвентаризация `tasks/`,
сверка ссылок по репо, toolchain-пробы). По решению владельца спецификация задачи не раздувается:
детализация уходит в `plan.md`.

## Решение

Следовать [design.md](design.md) без отклонений по существу: структура
`tasks/<тип>/<номер>-<слаг>/`, канон состояния в `task.yaml` (single writer — CLI, selfHash,
checksum согласованных документов), треки full/lite, config-driven CLI в `tasks/tools/`,
генерируемый `REGISTRY.md`, `tasks/AGENTS.md` + `flows/`, скилл `taskmaster`, растворение ролей
во вложенные `AGENTS.md`.

Уточнения, принятые по результатам ресёрча (проверено живыми пробами на Node v26.0.0):

1. **Запуск тестов CLI — через cwd, не позиционным путём**: `node --test <dir>` на Node 26 падает
   (`MODULE_NOT_FOUND`); рабочий паттерн — как в `apps/api`: `cd tasks/tools && node --test`
   (рекурсивно находит `*.test.ts`). Флаг `--experimental-strip-types` на Node 26 избыточен
   (`process.features.typescript = strip`), но сохраняется для совместимости с `engines: >=24`
   и консистентности со скриптами репо.
2. **`tasks/tools/tsconfig.json`** (extends `tsconfig.base.json`, `noEmit`) — для editor/LSP;
   в `npm run typecheck` (workspaces-only) не попадает, поэтому добавляется guard-скрипт
   `task:typecheck` (`tsc --noEmit -p tasks/tools`).
3. **`ci.yml` не правится**: `task:check` встраивается в цепочку корневого `npm test`
   (образец — `uispec:validate`), CI подхватывает автоматически; в CI-клоне без `tasks/`
   guard штатно скипает.
4. **Миграция «заявленных» задач** (`front-owner-001`, `infra-001`, `infra-002`): у них реальные
   `brief.md` в черновике, а adr/plan/result — нетронутые копии шаблона. Brief сохраняется
   (стадия «постановка»), шаблонные пустышки удаляются — их вернёт скаффолд при старте работы.
5. **Внутренние ссылки задач** (`](../task-…` — карта построена ресёрчем) переписываются
   миграцией на новые относительные пути. Существующая dangling-ссылка на удалённую
   `front-guest-003` в `front-ui-002/adr.md` остаётся как есть (историческая).
6. **Что не правим**: исторические документы и артефакты — `docs/ui-spec-kit/AUDIT.md`,
   `ROADMAP.md`, заметки в спеках и `contract-gaps.xml`, комментарии в коде приложений
   (`task-infra-003` и т.п.), `CHANGELOG.md`, тексты завершённых задач. Старые id остаются
   валидными идентификаторами через legacy-таблицу REGISTRY. Живые документы правим:
   корневые `AGENTS.md`/`README.md`, `docs/sources-of-truth.md`, `docs/architecture.md`,
   `docs/domain-model.md` (ссылка на `task-006/adr.md`), `docs/contract-pipeline.md`,
   `docs/ui-spec-kit/MANUAL.md`, `apps/*/AGENTS.md`.
7. **Не-задачные зависимости** («Docker Engine», «admin-доступ к репо») в `depends` task.yaml
   не входят (там только id задач) — остаются текстом в brief / `queue.rationale`.
8. **Растворение ролей**: единый буллет «самостоятельно не переводить в `согласовано`»,
   продублированный во всех шести ролях, не копируется шесть раз — вложенные AGENTS.md ссылаются
   на правило 11 корневого. При слиянии `frontend-agent.md` → `apps/client/AGENTS.md`
   актуализируются устаревшие места (байт-в-байт копии скриптов UISpec — давно симлинк).
9. **Extra-файлы задач** (`generation-report.md`, `design.md`) миграция не трогает: frontmatter
   снимается только с четырёх lifecycle-документов.
10. **`tasks/` — в git** (решение владельца 2026-08-16, поправка к исходному дизайну): проект
   учебный, процесс — часть оцениваемого. Каталог убирается из `.gitignore` и коммитится после
   миграции логичными порциями. Следствия: `task:check` в CI — настоящий гейт, а не скип;
   правки согласованных документов видны и в git, и через checksum-дрифт `task check`.
   `docs/` и `.opencode/` остаются локальными; переезд `docs/ui-spec-kit/` в git — будущая
   отдельная задача.

## Затронутые компоненты

`tasks/**` (структура, tools, шаблоны, документы процесса), корневые `AGENTS.md`, `README.md`,
`package.json` (npm-скрипты), `docs/sources-of-truth.md`, `docs/architecture.md`,
`docs/domain-model.md`, `docs/contract-pipeline.md`, `docs/ui-spec-kit/MANUAL.md`,
`apps/api/AGENTS.md`, `apps/client/AGENTS.md`, новые `packages/contracts/AGENTS.md`,
`packages/database/AGENTS.md`, `infra/AGENTS.md`, `tests/AGENTS.md`, `.opencode/agents/`
(удаляется), `.opencode/skills/taskmaster/` (новый), `.opencode/skills/worktree-isolated-agent/`
(один шаг). Код приложений, HTTP-контракт и generated-пакеты не затрагиваются.

## Последствия и компромиссы

- CLI становится несущим звеном процесса: его баг блокирует смену статусов. Компромисс принят
  осознанно (выбор C на brainstorming); смягчение — тесты на фикстурах, `task repair`,
  и то, что документы задач остаются читаемым Markdown.
- Часть правил зон переезжает в git-отслеживаемые AGENTS.md — принято владельцем явно.
- Старые id в исторических текстах перестают совпадать с путями — компенсируется
  legacy-таблицей REGISTRY и полем `legacyId`.

## Рассмотренные альтернативы

Зафиксированы в design.md и обсуждении: (A) только документы без инструмента; (B) CLI над
существующими frontmatter с ручным реестром; C-гибрид (frontmatter + манифест) — отвергнут как
худший из миров; полный YAML-канон (принят); отдельный npm-пакет сразу — отложен (config-driven
локально, вынос отдельной задачей).

## Совместимость и миграция

Миграция разовая (`task migrate`), порядок внедрения — в design.md, каждый шаг оставляет
репозиторий рабочим. Обратной совместимости путей не требуется: `tasks/` вне git, внешних
потребителей нет. CI-клоны без `tasks/`/`docs/` продолжают работать через guard-скипы.
Откат возможен до шага миграции простым удалением новых файлов; после миграции откат —
восстановление из локальной копии владельца (git-истории у `tasks/` нет — принятое свойство
процесса).
